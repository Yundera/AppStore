# SegmentStremioAddon — Rationale

## What deviation / exception is being requested

Two deviations:

1. **Root with user-directory access.** `ssa-backend` runs as `user: 0:0` while mounting
   the user directories `/DATA/Downloads` and `/DATA/Media`. CONTRIBUTING requires
   `user: $PUID:$PGID` for containers that touch
   `/DATA/Documents|Downloads|Gallery|Media`. The AppShield sidecar `ssa-proxy` also runs
   as `user: "0:0"`, matching the AppShield reference deployment; it mounts no volumes.
2. **`ALLOWED_PATHS` instead of `OAUTH_RESOURCE`.** The sidecar exempts `/api/` from the
   OIDC gate. CONTRIBUTING says machine/API clients should be gated with `OAUTH_RESOURCE`
   and that the `ALLOWED_PATHS` pattern should not be copied.

## Why it is necessary

**Root.** `ghcr.io/worph/segment-stremio-addon` is a Python/FFmpeg image whose HTTP server
binds port 80, a privileged port, and whose transcoder writes its working files into
root-owned paths inside the image. Dropping to a non-root uid fails the container at
startup.

**`ALLOWED_PATHS`.** The API client here is *Stremio itself* — the desktop, mobile, Android
TV and web players. Stremio fetches the addon manifest and then every catalog, meta,
stream, `/direct/:path` and `/transcode` URL directly, as a plain HTTP client with no
browser session, no redirect handling and no token acquisition. It is not an OAuth client:
it cannot perform an OIDC login, cannot complete an OAuth 2.1 authorization-code flow, and
has no way to attach a Bearer token to its requests. Putting `OAUTH_RESOURCE` in front of
`/api/` would return 401 to every Stremio request and the addon would not function at all.
The addon therefore carries its own credential instead: upstream derives
`API_KEY = sha256(HASH_API_SEED)[:16]` from `$APP_DEFAULT_PASSWORD` and embeds it as a path
prefix in every URL it publishes, so an unauthenticated request to `/api/` without the key
is rejected by the backend. The interactive setup page at `/` — the only surface a human
uses — stays fully behind the AppShield OIDC gate.

## Security mitigations in place

- **Both user-directory mounts are read-only** (`:ro`). The container cannot create,
  modify or delete anything under `/DATA/Downloads` or `/DATA/Media`.
- **The backend is not publicly reachable.** It sits only on the internal `ssa-internal`
  bridge network and carries no Caddy labels; only the AppShield sidecar joins `pcs`, so
  every request reaches the backend through AppShield.
- **The human-facing surface is gated.** Only `/api/` is exempt; `/` and everything else
  require the PCS's Authelia SSO login.
- **`/api/` still requires a credential.** The per-installation API key is required in the
  URL path; the exemption is from the *platform* SSO, not from authentication as such.
- The key is derived per installation from `$APP_DEFAULT_PASSWORD`, which is generated by
  Yundera and differs per PCS. It is never hardcoded in this compose file.
- Media paths are resolved and confined to the media root, so the read-only mounts cannot
  be traversed out of.
- No privileged mode, no host networking, no Docker socket, no capability grants, no
  published host ports.
- Memory limit of 256M and `cpu_shares: 70` on the backend.

## Alternatives considered and rejected

- **`user: $PUID:$PGID`** — the backend fails to start: port 80 is privileged and the
  runtime writes into root-owned paths in the image.
- **`OAUTH_RESOURCE` on `/api/`** — the correct pattern for machine clients that can speak
  OAuth 2.1, but Stremio cannot. It would 401 every addon request and break the app
  completely. (It also requires AppShield >= 2.0.7; the sidecar is now pinned at 2.0.9, so
  the version is no longer the obstacle — the client is.)
- **Removing `ALLOWED_PATHS` entirely** — the SSO redirect would be returned to Stremio in
  place of the manifest, and no catalog, stream or subtitle would ever load.
- **Narrowing the exemption below `/api/`** — every addon route lives under that prefix
  behind the API key, so there is no narrower prefix that leaves the addon working.
- **A stronger credential (long random token, rotated secret)** — desirable, but the key is
  derived inside the upstream image; changing its derivation is an upstream change and
  cannot be made from the app store.
- **Read-write mounts with `$PUID:$PGID`** — rejected regardless; the app only ever reads
  media, so read-only root is a smaller exposure than read-write non-root.

## Data protection

- The app stores no user data. It has no `/DATA/AppData/` volume; transcoded segments are
  produced on demand and are intentionally ephemeral.
- User media in `/DATA/Downloads` and `/DATA/Media` is mounted read-only, so an
  uninstall/reinstall cycle cannot touch it, and a compromise of the exempted `/api/`
  surface grants read access only — it cannot alter or delete anything.
